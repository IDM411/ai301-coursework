# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| environment | The environment facts stated in `## Candidate repro report`, read against the version and platform the `## Issue` body and `## Thread highlights` name as affected, and the environment fields the bug-report template asks for in `## Repo facts`. | Pass when the report names the tool version and the platform it ran on, plus any further axis the issue itself turns on (driver, shell, locale, editor, config), AND the version and platform it ran on either match what the issue names as affected or the report explicitly states the difference. A one-line environment record passes if it carries those facts. Fail when no environment is recorded, when an axis the issue turns on is absent, or when the run used a version or platform the issue does not name as affected and the report does not say so. | required |
| steps | The reproduction steps in `## Candidate repro report` and the inputs and configuration they reference, read against the trigger named in the `## Issue` body and any owner trigger note in `## Thread highlights`. | Pass when a reader with the named environment could re-run the report from the report's own text: the starting state and every input are given inline or reconstructible from it, the commands or UI actions are exact, and the sequence exercises the trigger the issue names. Fail when any input the outcome depends on is private, unshared, or referred to only in prose ("my config"), when a step the issue's trigger requires is missing, or when no steps are given. | required |
| behavior-shown | The artifacts in `## Candidate repro report` — output excerpts, logs, screenshots, control runs — read against the specific symptom named in the `## Issue` body. | Decide by the report's own stated outcome. If the report states the issue reproduced: pass when an artifact exhibits the specific symptom the issue names (the same error text, exit status, or observable output), and fail when the artifact shows a different failure, a graceful error where the issue reports a crash, merely that the tool runs, or nothing at all. If the report states it could not reproduce: pass when the artifacts show the attempt exercised the issue's named trigger on the issue's target (the right syntax, configuration, and version path), and fail when no artifact of the attempt is shown or the attempt targeted something the issue does not describe. | required |
| honesty | Every claim in `## Candidate claim comment` and the stated conclusion in `## Candidate repro report`, each read against the artifacts that same report shows. | Pass when each claim is backed by a shown artifact and every departure from the issue's stated conditions is named by the report itself. A report stating it could not reproduce PASSES this check when it shows the attempt and names what differed from the issue's conditions: a failed reproduction, honestly reported and evidenced, is a pass and never a fail. Fail when the package asserts a confirmation, a root cause, a frequency ("every single time"), or a scope its artifacts do not show, or when it narrates an artifact as the issue's symptom while the artifact shows something else. | required |
| disclosure-compliance | The contribution-policy line in `## Repo facts (captured …)`, read against what `## Candidate claim comment` and `## Candidate repro report` say about AI assistance. | First decide whether the stated policy requires disclosure for the artifact posted here, a comment on an issue thread. It does when the policy requires AI use to be disclosed in any form, or in issue comments. It does not when the repo states no AI policy, when the policy only asks contributors to understand and take responsibility for AI-assisted work, when it requires comments to be human-written without requiring a disclosure, or when it scopes disclosure to pull requests or code contributions. Pass when disclosure is not required for this artifact, or when it is required and the posted text states that AI was used and the extent of the assistance. Fail only when disclosure is required for this artifact and neither posted text discloses it. | required |
| comms-followability | `## Candidate claim comment` read against the `## Issue` body, and against the bug-report template asks and contribution policy in `## Repo facts`. | Pass when the claim comment is specific to this issue — it names what the author observed, the version or environment they observed it on, or a concrete next step tied to this code — such that it could not be pasted unchanged onto an unrelated issue, and it promises nothing the package supports. Fail when the comment is interchangeable boilerplate ("+1", "please assign me"), when it demands assignment or exclusivity, or when it promises a delivery timeline or a guaranteed fix. | required |

## Verdict rule

Accept when every required check grades `pass`. Reject when any required
check grades `fail` or `unclear`. Preferred checks are advisory and never
change the verdict. `unclear` counts as `fail`: proof that cannot be
verified from the package is proof that is not ready to post.
